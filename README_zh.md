# Hoozz Play OTA 工具

通过控制信道（TCP 54542，AES128-CBC 加密的 HOOZZ 协议）给 Hoozz Play 设备
（ESP8266 智能遥控器）升级固件的命令行 / 交互式工具。

[English](README.md)

升级过程：

1. UDP 发现设备（`HOOZZ?` 查询 / `HOOZZ:...` 应答）
2. 控制信道发 `INFO/FW_UPGRADE`，携带 `hoozz://<16位可见字符key>/<端口>`
3. 设备在该端口打开 OTA 隧道（tcp_crypto，"HoozzPlay" 握手认证）
4. 客户端先发 4 字节小端固件总长，再按 ≤1024 字节分片流式发送固件
5. 控制信道轮询 `INFO/FW_PROGRESS` 显示进度；100% 后设备约 3 秒自动重启
6. 重启后重新连接，读 `INFO/FW_VERSION` 验证升级结果

发现机制的要点（实测得出，也是本工具扫描能工作的原因）：

- 设备的应答**单播回查询的源地址**（它的 `recvfrom` 会把回复目标改写成
  发送方），所以查询必须从 54543 端口发出、在同一个 socket 上接收；
  从临时端口发出的查询会被回给临时端口，永远收不到
- 查询发两路：本机所有网卡的 /24 逐点单播探测（每 2 秒一轮）+
  255.255.255.255:54542 广播（每 1 秒一次，很多家用 AP 屏蔽客户端之间
  的广播，此时只有单播这路有效）
- 设备开机后还会向 255.255.255.255:54543 自广播 `HOOZZ:...` 约 4 秒，
  监听 54543 的扫描器顺带就能抓到刚上电的设备

## 环境要求

- Python 3.7+
- `pip install cryptography`
- 与设备在同一局域网

## 快速上手（交互模式）

```
python ota_tool.py
```

1. 自动扫描局域网 5 秒，列出在线设备（序号 / 设备名 / ID / IP）
2. 输入设备序号（s = 重新扫描，q = 退出）
3. 输入访问密钥（16 字节，见下面的格式说明；直接回车 = 16 字节全 0，
   出厂设备就是这个 key；如果之前用过该设备，会预填上次保存的 key）
4. 回车后工具立即拉取固件版本——这一步同时验证 key 是否正确；
   正确则继续提示输入固件的本地路径（同样预填上次保存的路径）
5. 确认后开始升级，实时显示 已发送/总量/设备端进度/速度
6. 升级完成、设备重启回来并验证版本后，key 和路径按设备 ID 记录到
   `config.json`，下次免输入

## 命令行（非交互模式）

```
python ota_tool.py scan [-t 秒数]          扫描并列出在线设备（默认 5 秒）
python ota_tool.py devices                 查看已保存的设备记录
python ota_tool.py version -d <设备>       查看设备固件版本
python ota_tool.py ota -d <设备> -f <固件>  执行 OTA 升级
```

`-d <设备>` 支持三种写法：设备 ID（14 位 hex，可用唯一前缀缩写）、
设备名、IP 地址。

`version` 和 `ota` 都支持 `--key`；`-f`、`-p` 仅 `ota` 有：

| 参数 | 命令 | 说明 |
|---|---|---|
| `--key` | version / ota | 访问密钥（缺省用该设备上次保存的，再缺省 = 全 0 key） |
| `-f, --firmware` | ota | 固件路径（缺省用该设备上次保存的路径） |
| `-p, --port` | ota | OTA 隧道端口（默认 54550） |

示例：

```
python ota_tool.py scan -t 8
python ota_tool.py version -d a848fad630e4
python ota_tool.py ota -d a848fad630e4 -f E:\fw\smart_ir.bin
python ota_tool.py ota -d "SMART IR" --key 00000000000000000000000000000000 -f smart_ir.bin -p 54551
```

## 访问密钥格式

设备的访问密钥是一个 16 字节的 AES-128 key（= 设备里设置的访问密码，
不足 16 字节补 0；没设过密码的出厂设备就是全 0）。输入支持三种：

| 输入 | 解释 |
|---|---|
| 直接回车（空） | 16 字节全 0（出厂设备） |
| 16 个 ASCII 字符 | 原样作为 16 字节 key |
| 32 位 hex | 解析成 16 字节 key |

## 设备记录（config.json）

与脚本同目录。按设备 ID（14 位 hex）保存：设备名、IP、访问密钥（hex）、
固件路径、最近在线时间。升级成功后自动写入；`python ota_tool.py devices`
可随时查看。这是本地文件，**不要提交到 git**（已在 .gitignore 里）。

## 常见问题

- **key 不对**：设备解不出正确的 magic 会直接断开 TCP 连接，工具报
  `device closed the connection`。换 key 重试（出厂设备先试空 key）。
- **扫描不到设备**：确认与设备在同一局域网；多网卡机器上工具会探测
  所有本机网段的 /24，一般无需干预。设备重启后前几秒在自广播
  `HOOZZ:` 消息，此时扫描也能抓到。
- **FW_UPGRADE 被拒绝（busy）**：上一次升级中断（比如客户端崩溃）后，
  设备还在 30 秒的隧道等待窗口内，会拒绝新的升级请求；窗口结束自动
  恢复。工具会自动重试（最长约 45 秒），一般无需干预。
- **OTA 端口连不上**：54550 同时是 IR 遥控隧道的端口，如果当时有
  其他 app 正开着 IR 隧道，换一个端口（`-p 54551`）。
- **升级中途断网**：设备端有看门狗式的超时（读分片 15s、握手 30s），
  超时会放弃升级并继续运行旧固件，设备不会被变砖。
- **验证与回滚**：新固件启动后若 10 秒内稳定运行即标记有效；连续 3 次
  启动失败会自动回滚到上一个分区。
